# DSA5208 Project 3 — Parallel Poisson Solver (MPI + OpenMP / CUDA)

Matrix-free finite-difference solver for the Poisson equation

    -∇²u = f  on [0,1]^d (d = 2, 3),   u = 0 on the boundary

using the Conjugate Gradient (CG) method. The project compares a serial
reference implementation with MPI, MPI+OpenMP and MPI+CUDA parallelisations.

> **Status:** serial version validated (V1); MPI + OpenMP version validated against the serial one (V2, V4);
> CPU experiments E1–E6 done on Vanda. MPI + CUDA version validated on 1 and 2 GPUs (V3); E7 (1 and 2 GPUs
> of one node) done.

## Features

| Item | Options |
|---|---|
| Dimension | 2D and 3D |
| Stencil | radius r = 1 (2nd order, 5/7-point) or r = 2 (4th order, 9/13-point) |
| Matrix storage | matrix-free (the stencil is applied on the fly; A is never stored) |
| Solver | standard CG (2 reductions / iteration) or single-reduction CG (Chronopoulos–Gear, 1 reduction / iteration) |
| Kernels | fused (fewer passes over memory) or unfused |
| Parallelisation | MPI Cartesian domain decomposition (`auto`: near-cubic process grid, `slab`: 1D); face halo exchange, blocking (`MPI_Sendrecv`) or non-blocking overlapped with the stencil on inner points; `MPI_Allreduce` for inner products; OpenMP threads inside each rank (`MPI_THREAD_FUNNELED`) |
| GPU (MPI + CUDA) | one GPU per MPI rank, all CG vectors in GPU memory; CUDA kernels for stencil, fused vector updates, deterministic two-stage reductions, boundary fill and face pack / unpack; halo exchange with CUDA-aware MPI (device pointers) or host staging (`--gpu-aware 0`) |
| Test problems | `mms`: manufactured solution with known exact solution (validation); `ones`: f = 1 (performance runs) |

No external numerical libraries (BLAS, LAPACK, cuBLAS, …) are used.

## Build

Requires a C++17 compiler; `make mpi` also needs an MPI library with `mpicxx` and OpenMP.
The test and plotting scripts need Python 3 with numpy and matplotlib (on Vanda:
`module load Python/3.11.5-GCCcore-13.2.0`).

The PBS scripts in `scripts/pbs/` contain `#PBS -P personal-CHANGEME`: replace it with your own
project (`sed -i 's/personal-CHANGEME/<project>/' scripts/pbs/*.pbs`) or pass `qsub -P <project>`.

```bash
make serial                                   # build/poisson_serial: g++ -O3 -march=native
make mpi                                      # build/poisson_mpi:    mpicxx -fopenmp -DUSE_MPI
make cuda NVCC=/path/to/nvcc                  # build/poisson_mpi_cuda: nvcc (src/gpu.cu) + mpicxx (host code)
make serial CXX=clang++ OPT="-O3 -mcpu=native"  # macOS / Apple Silicon (serial only)
```

Both clusters use the same toolchain, `foss/2023b` (GCC 13.2.0 + OpenMPI 4.1.6), so serial and parallel builds
use the same compiler and flags:

```bash
# Atlas (login node)
source /app1/ebenv && module load foss/2023b && make serial mpi
# Vanda: the login node is a VM, compile on a (whole, exclusive) compute node.
# Do not submit it while experiments are running: it starts with `make clean`.
qsub scripts/pbs/vanda_build.pbs
```

The CUDA version uses the NVIDIA HPC SDK module with the CUDA-aware HPC-X Open MPI. The A40 driver
on Vanda supports CUDA up to 12.9, so the CUDA 12.9 `nvcc` of the SDK is used (its default `nvcc` is 13.1):

```bash
module load nvhpc-hpcx-cuda12/26.1
make cuda NVCC=$(dirname $(which nvc++))/../../cuda/12.9/bin/nvcc    # -arch=sm_86 (A40)
```

## Run

```bash
# validation run: 3D, 128^3, 2nd order, report the error against the exact solution
./build/poisson_serial --dim 3 --n 128 --radius 1 --problem mms --verify --header

# performance run: 2D, 4096^2, 200 fixed iterations, 3 repetitions
./build/poisson_serial --dim 2 --n 4096 --problem ones --fixed-iters 200 --repeat 3 --header

# MPI: 64 ranks, pure MPI
OMP_NUM_THREADS=1 mpirun -np 64 ./build/poisson_mpi --dim 3 --n 512 --problem ones --fixed-iters 200 --header

# MPI + OpenMP: 8 ranks x 9 threads per 72-core node, overlapped halo exchange.
# Each rank is bound to 9 consecutive cores by scripts/bind_rank.sh (hwloc), see below.
OMP_NUM_THREADS=9 OMP_PLACES=cores OMP_PROC_BIND=close \
  mpirun -np 8 --map-by ppr:8:node --bind-to none -x OMP_NUM_THREADS -x OMP_PLACES -x OMP_PROC_BIND \
  scripts/bind_rank.sh ./build/poisson_mpi --dim 3 --n 512 --halo overlap --header

# MPI + CUDA: 2 ranks = 2 GPUs, CUDA-aware MPI (default) or host staging (--gpu-aware 0)
mpirun -np 2 ./build/poisson_mpi_cuda --dim 3 --n 512 --problem ones --fixed-iters 200 --header
mpirun -np 2 ./build/poisson_mpi_cuda --dim 3 --n 512 --problem ones --fixed-iters 200 --gpu-aware 0
```

On Vanda (foss/2023b, Open MPI 4.1.6) Open MPI's own `--map-by ...:PE=t` binding
hangs at launch across nodes and sometimes on one node, so the scaling scripts
start hybrid runs unbound and let `scripts/bind_rank.sh` bind local rank *i* to
the logical cores *i·t … i·t+t−1* (the cores `PE=t` would give).

Main options (`--help` for the full list):

| Option | Meaning | Default |
|---|---|---|
| `--dim 2\|3` | dimension | 3 |
| `--n N` (`--nx/--ny/--nz`) | interior grid points per dimension | required |
| `--local-n N` | weak scaling (MPI, CUDA): N points per process and dimension, global n = N × processes along that dimension | off |
| `--radius 1\|2` | stencil radius | 1 |
| `--problem mms\|ones` | test problem | mms |
| `--tol T` | stop when ‖r‖/‖b‖ < T | 1e-8 |
| `--maxit K` | maximum iterations | 10 · max(n) |
| `--fixed-iters K` | run exactly K iterations (scaling runs) | off |
| `--cg std\|single` | CG variant | std |
| `--fuse 0\|1` | fused kernels | 1 |
| `--repeat R` | repetitions | 3 |
| `--verify` | compute max error vs. exact solution (`mms` only) | off |
| `--save FILE` | write the final solution (raw float64, x fastest) — validation only | off |
| `--halo block\|overlap` | halo exchange (MPI; the CUDA version implements `block` only) | block |
| `--decomp auto\|slab` | process grid (MPI) | auto |
| `--gpu-aware 0\|1` | CUDA-aware MPI (1) or host staging (0) (CUDA version) | 1 |
| `--sync-timers 0\|1` | diagnostics (MPI, CUDA): timed `MPI_Barrier` before every Allreduce, so that waiting for the slowest rank (`t_wait`) is separated from the reduction (`t_allreduce`); adds one barrier per reduction | 0 |
| `--header` / `--verbose` | CSV header / human-readable summary on stderr | off |

### Output

Each repetition prints one CSV line on stdout:

```
impl,problem,dim,radius,nx,ny,nz,N,nnz,nodes,ranks,threads,gpus,decomp,halo,cg,fuse,
gpu_aware,mode,tol,iters,converged,t_setup,t_solve,t_iter,t_halo,t_allreduce,t_compute,
rel_res,true_rel_res,err_inf,repeat_id,host,t_bc,t_wait
```

- `N` = number of unknowns, `nnz` = nonzeros of the implicit matrix A
- `t_setup` = allocation and right-hand side generation (not part of `t_solve`)
- `t_iter` = `t_solve / iters`; `t_solve` also contains the initial residual r₀ = b − A x₀ (one extra
  operator application), so `t_iter` is about 1 / iters too large (1 % at 100, 0.5 % at 200 iterations)
- `t_halo`, `t_allreduce`, `t_compute` split `t_solve` by category. `t_halo` includes the physical
  boundary fill (`t_bc`, also present with one process) and the packing of non-contiguous faces.
  `t_allreduce` includes the time a rank waits in `MPI_Allreduce` for slower ranks, unless
  `--sync-timers 1` moves that waiting into `t_wait` (the CSV columns `t_bc`, `t_wait` were added on
  11/11; files measured before have no such columns)
- `rel_res` = CG recursive residual; `true_rel_res` = ‖b − Ax‖/‖b‖ recomputed after the solve
- `host` = machine the run was measured on
- `decomp` = process grid, e.g. `auto:4x4x4` (processes along x, y, z)
- MPI runs: `t_solve` is the maximum over ranks; `t_halo`, `t_allreduce`, `t_compute`, `t_bc`, `t_wait` are
  averages over ranks

> **Timing data policy:** all timings used in the report (serial baseline and parallel runs) are measured on the
> same cluster node type with the same compiler and flags. Runs on a personal laptop are used only to check
> correctness and scripts; their timings are not reported.

## Running on the cluster without wasting core-hours

Vanda charges for reserved time, even if a job hangs. The scripts therefore use four guards:

1. every configuration runs under `timeout` (`RUN_TIMEOUT`, `--timeout`); a timeout aborts the whole job,
2. tight walltimes, `-r n` (no automatic rerun) and `-k oed` (live output),
3. `scripts/pbs/watchdog.py` on the login node deletes jobs stuck in a start-failure loop or without output for 15 min:
   ```bash
   nohup python3 scripts/pbs/watchdog.py --stall 900 > /dev/null 2>&1 &   # log: ~/dsa5208/watchdog.log
   ```
4. staged submission: a short smoke run (`scripts/pbs/vanda_smoke.pbs`, 10 iterations) on 1 and 2 nodes before
   the full experiments on 1, 2 and 4 nodes (`scripts/pbs/submit_scaling.sh`).

Result files are never appended to by a second run: `scripts/run_scaling.sh` writes a re-run of an
existing `results/<exp>_vanda_n<N>.csv` to `results/<exp>_vanda_n<N>_<jobid>.csv`, and the GPU
scripts tag every file with the GPU count and the job id. Each GPU job builds in its own
directory (`build/job_<jobid>`), so a 1-GPU and a 2-GPU job can run at the same time.

## Test problems

- **`mms`**: u(x) = ∏_d g(x_d) with g(t) = sin(πt) / (2 − cos(πt)), and f = −∇²u computed analytically.
  g is zero and odd about t = 0 and t = 1, so the odd reflection used by the r = 2 stencil at the boundary is exact.
  A plain sin(πx)sin(πy) solution is avoided on purpose: it is an eigenvector of the discrete operator, and CG would converge in one iteration.
- **`ones`**: f = 1. All Fourier modes are present, so the CG iteration count grows like O(n), as in a realistic solve.
